2026-08-26 23:48 EDT
Goal: find residual, bind two views, simulate only on validated edges, scale city → world without analog leak.

## What is already logical
- Types before dollars. Query our index first.
- Two viewpoints on one residual. That *is* DCLM. 115 vs 93 is the fact.
- Stable IDs. Change needs a why and a better source.
- Four relation planes. Award hole allowed.
- Belleville is a template identity, not a stencil that overwrites the next city.
- Association types travel (local-GC ↔ hospital-family). Names do not.

## Where it can fail (not ideology — load)
1. **Type explosion.** If every new sentence becomes a new residual type, the index stops being queryable. Fix: a new type must survive “would this change a decision on this entity?” If no, it is a note, not an ID.
2. **Hole = never ship.** Dual view is required. A named hole still lets the other view work. Incomplete ≠ invalid. Invalid = two views smashed into one cell.
3. **Travel without a lock.** “Belch–QHC type” on a new city is a *search pattern*. The new city’s GC and hospital keep their own IDs. Pattern ≠ analog $.
4. **World too early.** Parent 10-K is a viewpoint on the parent, not on the plant. Label the geography on the ID (`BEL.PG.*` vs `US.PG.*`).

## Suggestion (does not replace the ideology)
Add one invertibility check on every write: can we walk the ID back to the source sentence? If not, the metric is not in the system yet. That is the closed loop you already asked for on TDI.

No rewrite of the law. Tighten the load so agents do not burn residual hunting types that will never bind.
