# INDEX-LIVE — the plate is handles, not a warehouse
2026-08-27 00:40 EDT
Law. Bake into every later city.

## Principle
We index organs. We do not have to keep their last number.
If the ID, GEO grain, YEAR rule, SRC, and STAMP are right, the value can be pulled when a question arrives.
A sealed number in a markdown file is a *cache*, not the record of truth.
Truth is the public (or tenant) page the handle points at.

## What must be stored
`ID` · `GEO` allowed grains · `SRC` (url / table / tenant book) · `STAMP` rule · overlay class (STRONG/WEAK/ABSENT vs atom and vs ceiling) · unit · split-pairs · Δ gates
That is the index. That is the product.

## What may be cached
Last pulled `X` + `YEAR` + fetch date. Useful. Disposable.
If the cache and the live page disagree, live wins after the pair-gate. Cache becomes Δ.TIME or Δ.BOOK.

## What must not be stored as if it were the city
Blended columns. CMA numbers under a CSD ID. Vendor-metro under a city TTI. A tenant kWh as civic peak.
Those are index defects. They make live pull lie.

## Pull
Question → resolve ID+GEO → if ABSENT return N/A → if HOLE return HOLE + the SRC to hunt → if SEALED-handle, fetch SRC now → stamp the cache.
Do not walk the whole warehouse "just in case."

## Completeness
The Canadian frame is *index-complete* when every PLAYGROUND family has a handle on every CSD we care about — SEALED-handle, N/A, or HOLE-with-SRC — not when every cell holds a number.
Numbers can wait. Missing handles cannot.

## Private / live feeds
Same rule. Tenant declares the ID it can serve. We pull when the question names that tenant. We do not ingest their lake into ours.

## Agent rule
Prefer writing a handle + SRC over copying another paragraph of last year's budget.
Reprint of a cached number, with no new vintage, is Δ.search = 0. Drop it.
