# Viewpoints — required, not a nice-to-have
2026-08-26 23:47 EDT
DCLM binds two constraints on the same residual. One number is not the fact. The fact is the set of validated viewpoints. If a viewpoint is missing, the ID is incomplete — it is not “good enough for now.”

## Required viewpoint pairs (already in the Belleville book)
| residual | viewpoint A | viewpoint B | do not collapse |
|----------|-------------|-------------|-----------------|
| Police staff | BEL.BPS.AUTH 115 | BEL.BPS.DEPLOY 93 | authorized ≠ on the floor |
| QHC people | family ~2,600 | 1,700 staff + 364 privileged | family ≠ BGH site |
| City money | gross estimates | tax levy | spend ≠ levy |
| Plant people | P&G >1,000 | 150 contractors (2017 vintage) | FTE ≠ contractor layer |
| Hire | rolling term | first-year stay unknown | posting ≠ stay |
| Contractor | BID | AWARD | invited ≠ won |
| Chamber | member band | civic/operator check | listed ≠ operating |
| Geography | CSD | CMA | city ≠ region |
| College | faculty 141 (2024) | remaining after cuts | old complement ≠ now |

## Rule
1. Every residual ID must name at least two viewpoints or name the missing one as a hole.
2. A search that returns only viewpoint A has not finished.
3. Changing A does not change B. Each has its own ID and its own validation.
4. Simulation uses both. Affinity = they describe one residual. Friction = they were smashed into one cell.

This is the data model. Not a documentation preference.
