# DCLM base invertibility
2026-08-26 21:44 EDT

Every specialized pack is the base model plus constraints.
Reverse-engineer any pack and you must reach the unconstrained base by the same logic.

## Base (no constraint applied)

- Pole A / Pole B
- L1–L5
- Debate 1–7
- Residual unit (unnamed until the pack names it)
- Invertibility
- P1 vs P2
- Isolation + correlation gate
- Tweak slots empty: n, k, complexity, wait, acuity, friction, affinity

That object is `dclm.base`. It does not score a school, a tumor, or a SKU. It is the meter before a dataset exists.

## Forward

`dclm.base` + pack dictionary + instance (n, k, complexity, env) → scored pack.

## Reverse (required, same steps for every pack)

1. Strip instance values (this school's n, this trial's k).
2. Strip pack units (hours of re-key, months of PFS, fee per SKU).
3. Strip pack graph (parent–secretary, BRCA–PARPi, SKU–policy).
4. What remains must be `dclm.base` with empty tweak slots.
5. If anything remains that cannot be named in the base table, the pack is graft. Rebuild.

Oncology reverse, school-board reverse, amazon_ops reverse — same five steps. Different dictionaries. Same landing.

## Test

If two packs reverse to two different bases, the model is broken.
If a pack cannot reverse (a constraint has no off-switch), mark INV = fail and do not sell the score.
