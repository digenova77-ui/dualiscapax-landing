# Tweak ladder — class → subclass → named instance
2026-08-26 22:27 EDT

A prior instance in the same industry is a **field list**, not a scored twin.
Ottawa is not Toronto. A 20-school board is not a 550-school board. Transport rural is not transport subway-adjacent.

Do not print counterparties on the public homepage.

## Three altitudes

| altitude | what it is | what it may carry |
|----------|------------|-------------------|
| class | kind of work (school board, plant, club) | empty slots only |
| subclass | a repeatable difference that survived smash (rural busing, French-language, Catholic governance, metro density) | meters that *that* difference needs |
| instance | one legal name | scored values, weights, next_cut |

Class tweaks can be thousands.
Subclass tweaks can be 10^5.
Instance cases can be 10^6+ as each named entity specializes.
That explosion is correct. Collapsing it back into "the education model" is graft.

## School-board family (pattern)

If two Ontario boards already taught us that energy payor, site count, and bus contract matter, those are **questions we know to ask**. They are not Ottawa's numbers and not Toronto's weights.

Before the chair for a new board:
1. Legal name (instance).
2. Public size: school count, enrolment band, geography (one municipality / many / remote).
3. Transport shape if public (own fleet / contracted / pass-through).
4. Which subclass slots those facts open.
5. Six core lines + only the modules those slots need.
6. Weights stay blank until that board's own data or grant fills them.

A 90-school rural board and a 550-school metro board can share the class and still disagree on every weight.

## Rule

Copy a *question* from a sibling.
Never copy a *score*.
If the new board targets different metrics, it is a new instance — possibly a new subclass — not a cloned run.
