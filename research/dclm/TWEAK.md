# DCLM tweak law — same model, measured fit
2026-08-26 21:42 EDT

The model does not change by niche.
The **tweak** changes so the same poles can read this dataset, at this size, at this complexity, in this environment — and so the environment can read back what the dataset can actually support.

## Same

Poles A/B. Layers L1–L5. Debate 1–7. Residual unit. Invertibility. P1 vs P2. Isolation unless a shared meter ID has data.

## Tweak (required on every pack load)

| Field | Measures | Vice versa |
|-------|----------|------------|
| `n` | Dataset size | Environment sets minimum n before a score |
| `k` | Distinct classes in the set | Environment sets how many classes it can bind |
| `complexity` | Relationship depth, missingness, shadow copies | Environment forbids inventing missing joins |
| `wait` | What this set still lacks | Application holds until that lack is filled |
| `acuity` | Smallest object the set can tell apart | Application may not claim finer grain |
| `friction` | Waste in this set's units | No imported friction units |
| `affinity` | Facts that stay true across views in this set | No merge the set does not join |

A pack with empty n, k, complexity is a generic five-layer. That is not Dualis.

## Vice versa

Dataset → application: claim only what n, k, and complexity support.
Application → dataset: ingest only fields the environment can constrain.
Do not copy n across packs. A large Amazon table does not score a school with n = 0.
