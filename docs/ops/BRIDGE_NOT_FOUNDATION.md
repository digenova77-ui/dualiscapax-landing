# Bridge ≠ foundation

Document control: `ED-OPS-20260911-BRIDGE-GATE-V1`  
Status: **operating rule for research artifacts**. Not a Spine invariant. Not I17-as-law.

Seat line, 2026-09-11:

> Allowed to build the bridge.  
> Not allowed to declare that the bridge is part of the foundation until it survives testing.

## Who may do what

| Act | Allowed | Forbidden |
|---|---|---|
| Identify a necessity | yes | calling the necessity a solved problem |
| Classify a boundary | yes, with evidence class | collapsing “not found” into “impossible” |
| Write a bridge record | yes | writing it into `AGENT/SPINE.md` or sealed packs |
| Build tests, schemas, models, sims | yes | treating sim convergence as physical proof |
| Attack the bridge | required | erasing a failed bridge |
| Promote the bridge into foundation | **no, until a test receipt exists and Seat says so** | self-certification by the agent that wrote the bridge |

Foundation here means: Spine, sealed packs, `COUNSEL_SEALED`, lander law, live deploy, authority.

A file under `docs/ops/`, `schemas/`, or `06_ENCYC_*` is a **bridge object**. Putting it in git does not promote it.

## Survival

A bridge survives only when all of these are true:

1. Discriminating test exists and has a result (`PASS` / `FAIL` / `UNRESOLVED`).
2. Result is `PASS` inside the declared domain.
3. Search domain and limitations are declared (Krypton: not-found ≠ nonexistent).
4. The proposing agent is not the sole certifier.
5. Seat records promotion. Silence is not promotion.

Fail, unresolved, or missing receipt → stays a bridge. Record remains. Next agent continues from the surviving boundary.
