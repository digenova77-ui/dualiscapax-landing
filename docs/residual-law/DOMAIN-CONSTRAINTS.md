## The principle

**Same residual-law logic. Different constraints per domain.**

We do **not** apply one generic meter the same way across every business or industry.

We use the **same logic** everywhere:

- Capacity is measured  
- Residual is priced  
- Fuel is the sole capacity unit  
- Residual Cost Peg holds  
- DCLM is non-bypassable  
- One law, free will, residual honesty  

…and we **specialize the constraints that are measured** so each domain’s residual is measured *perfectly for that domain* — not approximately with a one-size-fits-all counter.

## What changes (constraints measured)

Each domain defines **what counts as residual burn** and **how it is quantified**, under the same peg.

| Domain | Constraints measured (domain-perfect) | Not a general substitute |
|--------|----------------------------------------|---------------------------|
| **Medical** | Path residual, simulation residual, literature-synthesis residual, irreversible state in sealed packs; clinical surface = simulation + literature only | Not “tokens per chat” as if it were consumer AI |
| **Engineering** | Design-run residual, host-safe process residual, materials/compute residual, thermodynamic irreversibility under DCLM | Not a flat “API call” tax for every engineering act |
| **Industrial** | Process residual, capacity-constrained production residual, measured work against prepaid seat | Not open-ended vendor bleed or generic SaaS seats |
| **Math** | Formal residual (proof steps, path-exhaust DAG cost, commitment-chain cost), verification residual | Not the same unit as a medical path sim without mapping |
| **Science** | Field residual, biocomputational residual, experimental simulation residual | Not a single “science credit” that ignores field structure |
| **Adaptive intelligence** | Compute residual against Fuel after Prove; still domain-tagged when the run is medical / engineering / math / science | Not unlimited free depth |

**Residual classes** in the Metering API (`compute` | `structure` | `irreversible`) are the *shared encoding*.  
**Domain constraints** decide *what* is counted into those classes and *how much Fuel* a given residual act is worth — so measurement is perfect for that domain, not averaged across industry.

## What we refuse

- One general residual rate for “all business”  
- One generic SaaS meter pasted onto medical, engineering, and math alike  
- Parallel capacity currencies per industry (Fuel remains sole unit)  
- Softening product quality for larger spend  
- Equity / yield / cure claims dressed as domain depth  

---

## Implementation rule

1. **Logic is global** — peg, Fuel, DCLM, Prove, one law.  
2. **Constraint tables are domain-local** — what burns, how much, under which residual class.  
3. **Metering API stays one surface** — domain tags + residual_class + quantity in Fuel.  
4. **Open research stays free** in every domain; adaptive depth burns domain-perfect residual against the same seat.  
5. **Agent copy** describes what this does *for them* in their domain — never “we have a general platform for all industries.”

---

## Agent rule

When extending residual-law into a domain: keep the logic identical; define domain constraints that measure *that* residual perfectly; never invent a second capacity unit or a preferred-tribe rate.
