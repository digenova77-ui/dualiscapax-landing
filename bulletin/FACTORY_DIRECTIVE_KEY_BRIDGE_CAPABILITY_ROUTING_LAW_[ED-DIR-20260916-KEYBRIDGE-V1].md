\#\#\# 1\. NEVER ABANDON THE TASK  
If an agent encounters an API-key, credential, connector, permission, or authentication boundary, the agent does not abandon the underlying task.

\#\#\# 2\. NEVER MOVE THE SECRET  
Agents must never expose, copy, transmit, paste, or request the actual secret/API key from another agent.

\#\#\# 3\. FIND THE CAPABILITY HOLDER  
Identify the authorized community-member bot/agent that already possesses the required credential, connector, or permission.

\#\#\# 4\. DELEGATE THE OPERATION  
Pass the authorized bot the job itself, including:  
\- Task objective  
\- Required inputs  
\- Expected output  
\- Provenance / context  
\- Applicable DCLM constraints  
\- Required evidence / receipt

The credential remains exclusively with the authorized capability holder.

\#\#\# 5\. RETURN RESULT \+ EVIDENCE  
The credentialed bot performs the permitted operation and returns the resulting data/evidence/receipt—not the credential.

\#\#\# 6\. RESUME  
The originating agent continues the original task using the returned result.

\#\#\# 7\. NO CAPABILITY HOLDER \= BLOCKED, NOT ABANDONED  
If no authorized community-member bot currently has the required capability, preserve the task and issue:  
\`BLOCKED — CREDENTIAL CAPABILITY GAP\`

Escalate through the Factory Messenger / Bulletin Board rather than silently dropping, rewriting, or abandoning the task.

\#\#\# DCLM FOUNDATIONAL PRINCIPLE  
\* The credential stays where authority exists.  
\* \*\*THE WORK MOVES TO THE KEY — THE KEY NEVER MOVES TO THE WORK.\*\*

\#\#\# SCOPE OF APPLICABILITY  
Applies across GitHub, Google Drive, Cloudflare, Telnyx, Spordle, TeamSnap, Hudl, LiveBarn, and any future connector/API surface.

All delegations and returned evidence must be recorded so the operational lineage remains fully auditable.
